# Momentum place flow (FULL AUTO)

1. Screener-run QA Bot PASS required before any BUY pack is accepted.
2. Place-QA via QA Bot (mirror A cash truth) before prepare/place.
3. `INSUFFICIENT_CASH` → GATE_OK; log FAIL; do not place; do not score as playbook AVOID.
4. If cash later frees (closes): pull fresh A cash → **re-ask QA Bot place-QA** with new snapshot → place only on new PASS.
5. Never self-PASS / reuse prior FAIL pack. AVOID: `PLACE_WITHOUT_QA_BOT_RECHECK`.
6. **Single-use verdict lock (2026-10-15, VTRS/STLD dup incident):** before EVERY place-trade (routine AND parent chat): live `get-my-positions-and-orders` with top-level `timestamp`/`asOf` **<120s** → `python -m momentum_qa.place_lock acquire --verdict <qa-verdict.json> --symbol <SYM> --caller <eod-routine|parent-chat> --positions-json <live.json>` → only on exit 0: prepare-trade → place-trade → `place_lock mark --lock <path> --status PLACED|FAILED --order-id .. --position-id ..`. Exit 2 LOCK_HELD / 3 ALREADY_HELD / 4 POSITIONS_STALE|RETRY_NOT_ALLOWED → do NOT place. Missing timestamp = POSITIONS_STALE. Same verdict sha never re-places; FAILED/EXPIRED retry needs `--retry-after-fail` + fresh QA verdict. PM trail/close use `--allow-held`.
7. Pack shape (playbook 2026-10-05): **unlimited stocks**, etf_buys ≤ 1, ≤$1000/name, cash gate.
8. **Place audit rows (QA Bot 2026-10-21, CRL post-fill).** Routines never hand-write audit JSON. **RUN_ID CONVENTION:** `run_id` = the pack's `screener_run_id` on every SKIP / PLACE_RUN_START / FILL / FILL_AMEND / PLACE_RUN_END row, and every one of those rows also has a top-level `screener_run_id` (plus `verdict_sha256`). Rows are written to `momentum_audit/<IL date in the run id>.jsonl`. Every command is idempotent and safe to re-run. Rows written before this convention (run_id `place-<screener_run_id>`) are still recognised.
   1. Before the first place: `./screener-venv/bin/python -m momentum_qa.place_audit start --screener-run-id <id> --verdict <qa-verdict.json> --symbols SYM1,SYM2`
   2. Per authorized symbol, **in this exact order** (QA fixes3 2026-10-21; same as `momentum_audit/routines/placer-routines-20261021.md`):
      - **(a) Quote + guard.** Use the screener row's `etoro_place_symbol` and `etoro_instrument_id` (every BUY row carries one; e.g. Agilent = `A.US` / 1764, AT&T = `T.US` / 1030). Read the live quote (`get-instruments-overview`, write_to_file), then `./screener-venv/bin/python -m momentum_qa.instrument_map guard --symbol SYM --quote <ask> --quote-symbol <live quote symbol> --quote-instrument-id <live quote instrumentId> --instrument-id <screener row etoro_instrument_id> --screener-rows <screener.json>`. **Live quote fields** (`user-Momentum-HHHGDTJ get-instruments-overview {symbols:[<etoro_place_symbol>]}`): `instruments[].market.instrumentId` → `--quote-instrument-id`, `instruments[].market.symbol` → `--quote-symbol`, `instruments[].quote.ask` → `--quote` (the `quote` object itself has only ask/bid/spread/asOf, no id). The guard requires live quote id == screener row id == `--instrument-id` and live symbol == place symbol (else QUOTE_ID_MISMATCH), and looks every id up in `instrument_ids.json` + the remap table: an id that belongs to another ticker → ID_SYMBOL_MISMATCH (e.g. POIS + 1001 = AAPL, T + 100528 = Threshold); an id in neither → INSTRUMENT_ID_UNVERIFIED. Exit **0** = go. Exit **3** = no place: INSTRUMENT_ID_REQUIRED (no `--instrument-id`), QUOTE_ID_MISMATCH (live quote id/symbol missing or not equal to the row id / place symbol), ID_SYMBOL_MISMATCH (id is another ticker per the cache/remap table, e.g. T + Threshold 100528), SYMBOL_MAP_MISMATCH (id ≠ the remapped stock id), INSTRUMENT_ID_UNVERIFIED (id not in the cache, or no screener-row id → fail closed), QUOTE_DEVIATION_GT_20PCT, QUOTE_GUARD_INPUT_MISSING (no reference close → fail closed). The name gets a SKIP row with that protective code.
      - **(b) Classic freshness.** `./screener-venv/bin/python -m momentum_qa.precheck classic-fresh --classic-raw <Classic read> --max-age 900 [--save]` (`--max-age` above 900 → exit 2 MAX_AGE_TOO_HIGH). Exit ≠ 0 → do one fresh Classic read (`user-OfersClaw5 get-my-positions-and-orders`, write_to_file) and retry once; still failing → no place (SKIP `STALE_CROSSBOOK_FAIL_CLOSED`, protective). `--save` rewrites the cross-book snapshot incl. `instrumentIds`.
      - **(c) Positions.** Fresh `get-my-positions-and-orders` read with top-level `timestamp` **<120s**.
      - **(d) Lock.** `place_lock acquire ... --positions-json <(c)> --instrument-id <the same screener row id>` (step 6). Exit **5** ID_SYMBOL_MISMATCH (cache/remap id→symbol check; no lock written) or **3** ALREADY_HELD → no place; 2 LOCK_HELD / 4 POSITIONS_STALE|RETRY_NOT_ALLOWED → no place.
      - **(e)** prepare-trade + place-trade with `etoro_place_symbol`. A prepare rejection is logged as `PREPARE_REJECTED_GUARD` (id mismatch / quote sanity / invalid SL / insufficient balance → protective) or `PREPARE_REJECTED_BROKER` (market closed / not tradable / min size / transient → intentional).
      - **(f)** `place_lock mark --lock <path> --status PLACED|FAILED --order-id .. --position-id ..`.
      - **(g)** `place_audit fill ... --fee <USD>` (next item).
   5. After each fill: `./screener-venv/bin/python -m momentum_qa.place_audit fill --screener-run-id <id> --verdict <qa-verdict.json> --symbol SYM --position-id N --order-id N --units X --open-rate X --amount 1000 --fee <USD> --sl X`
      - `--fee` is required: use `orders:lookup` `positionExecutions[].openingData.fees`.
      - rvol_at_entry and setup come from the screener pack row.
      - If a FILL row was written without a fee, add it with `place_audit amend-fee --symbol SYM --position-id N --fee X --source "<read + xRequestId>"`. This appends a FILL_AMEND row and never edits the original row.
   6. Every pack BUY that was not placed: `./screener-venv/bin/python -m momentum_qa.pack_skips --screener momentum_audit/screener-run-<id>.json --verdict <qa-verdict.json> [--placed SYM,...]`
      - The reason comes from the QA verdict (authorize false + code/reason, or ALREADY_HELD / INSUFFICIENT_CASH markers).
      - Names with FILL / PLACE_RUN_END / POSTFILL rows count as placed automatically.
      - Use `--no-audit` for a dry run.
   7. Last: `./screener-venv/bin/python -m momentum_qa.place_audit end --screener-run-id <id> --verdict <qa-verdict.json> --placed SYM,... --skipped SYM,...`
   8. Daily feedback (`./screener-venv/bin/python -m momentum_qa.feedback_daily [YYYY-MM-DD]`; `--help`, `--stdout`):
      - From **2026-10-21**, a pack BUY with no FILL/placed row and no SKIP row for its run = `MISSING_SKIP_ROW`.
      - `gate_ok_codes` / `protective_reject` are counted from SKIP rows, as **separate** classes (QA 2026-10-21 re-review): GATE_OK (INSUFFICIENT_CASH, ALREADY_HELD, CROSS_BOOK_HELD, caps, ...) → `gate_ok_codes` only; PROTECTIVE_REJECT = only true protective refusals (instrument guard: QUOTE_DEVIATION_GT_20PCT / SYMBOL_MAP_MISMATCH / QUOTE_GUARD_INPUT_MISSING / INSTRUMENT_ID_REQUIRED|UNVERIFIED|UNRESOLVED, ID_SYMBOL_MISMATCH, stale cross-book fail-closed, STALE_POSITIONS / POSITIONS_STALE fail-closed, PREPARE_REJECTED_GUARD, SL_ABOVE_ASK) → `protective_reject` only; INTENTIONAL_SKIP (DWM/regime/event freeze, lock held, market closed, not tradable, PREPARE_REJECTED_BROKER) → KEEP, counted in neither. Only the reason code decides: an unknown code (incl. bare `PREPARE_REJECTED`, the literal `PROTECTIVE_REJECT` or the literal `GATE_OK`) with a self-declared `gate` label is `SKIP_UNGATED` (AVOID).
9. **Symbol normalisation (2026-10-21).** All held/duplicate checks compare **base tickers** (`instrument_map.base_symbol`: `A.US` / `X.RTH` → `A` / `X`) **and instrumentIds** (id match OR symbol match; id 100022 VAULTA never equals Agilent `A`). This covers precheck lots/orders, place_lock ALREADY_HELD (`--instrument-id`), the screener Classic cross-book drop (`classic_book`, snapshot keeps `instrumentIds`), pack_skips, postfill_check matching, open_gap_check, soft_flags held set, and books overlap (`.US` / `.RTH` stripped).
   - **held = id match OR base-symbol match** (QA 2026-10-21 HIGH); both always run. A mismatched instrumentId never overrides the symbol: if a request id is known as a different ticker (`AAPL` + 100022 VAULTA or 1764 Agilent), it is `ID_SYMBOL_MISMATCH` → guard exit 3, place_lock exit 5 (no lock), screener cross-book SKIP, postfill bad input. On held positions a known id only refines a consistent eToro symbol (`A`+100022 → crypto `CRYPTO:A`); otherwise the symbol wins.
